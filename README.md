# FileDrop · 局域网文件快传

在**同一 WiFi / 局域网**下，任意设备互传文件：电脑、手机、平板——手机装个 App（或只用浏览器），电脑开个 exe。
专为个人 1–4GB 级别大文件设计：自动分块、断点续传、SHA-256 校验、配对令牌防误传。
顺带一条**文本快传**通道：验证码、命令、地址不用包装成文件，粘过去对面一键复制。
还能**互相看见**：页面上列出同网的其他 FileDrop 设备，点「请求上传」由对方屏幕上的人批准，
换一枚只认本机 IP、半小时过期的临时写授权。

## 适用场景
- 手机 ↔ 电脑、手机 ↔ 平板、平板 ↔ 电脑 —— **谁开服务谁是主机**，其余设备扫码加入
- 主机可以是电脑（双击 exe），也可以是手机（打开 App）；不装 App 的设备用浏览器扫码即可
- 设备基本在同一局域网；跨网场景暂需额外打洞/中继（后续做）

## 运行（Windows）
两种启动方式：
- **托盘版（推荐）**：双击 `filedrop-tray.exe`，后台拉起无界面服务，自动打开传输页面；任务栏托盘菜单可「打开传输页面 / 退出」。
- **无界面版**：双击 `filedrop.exe`（已编译好，零依赖），自己开浏览器访问控制台打印的地址。

或自行编译：
```bash
go build -o filedrop.exe .
go build -o filedrop-tray.exe ./tray
./filedrop.exe
```
可选参数：
```
-port 28080    监听端口（默认 28080）
-dir  received 接收目录
-no-auth       关闭配对令牌（仅本地测试用）
```
> 启动后网页会显示本机连接地址的**二维码**，手机 / 平板扫一扫即可打开（已含上传令牌），免输地址。
>
> 首次自行构建需联网拉取两个依赖（`skip2/go-qrcode`、`getlantern/systray`）；国内建议先设 `GOPROXY=https://goproxy.cn,direct GOSUMDB=off`。
启动后控制台会打印「本机连接地址」，形如：
`http://192.168.1.20:28080/?t=xxxx`

## 使用
1. **电脑端**：打开 `http://localhost:28080/`（或控制台地址），页面显示「本机连接地址」。
2. **手机 / 平板**：在浏览器里打开控制台打印的带令牌地址（复制粘贴或后续扫码）。
3. **发送（上传）**：在手机/电脑页面点「发送」选文件（**可多选**）→ 进入**任务队列**，每个文件独立显示进度/速度/ETA，可逐个取消也可全部取消；取消或中断后再选同一文件会**原地续传**（队列里点「续传」即可）。界面显示的是服务端**真实落盘文件名**，与用户选的名字不同时（含非法字符被清洗、同名避让改名）会在完成行注明「已存为 …」。
4. **接收（下载）**：页面列出接收目录里的文件（**新的在最上面**，含子目录里的），点「下载」即用浏览器原生保存（支持断点续传）；勾选多个文件可**打包成 ZIP 一次下载**（服务端流式打包，不占磁盘）。
5. **文件夹上传**：桌面浏览器里点「选择文件夹上传」，保留目录结构落盘（手机浏览器与 App 内该入口自动隐藏）。
6. **同名冲突**：接收端已有同名同大小但内容不同的文件时，会问一次「覆盖还是共存」——选择对整批生效；共存的自动改名「名字 (1).ext」，同内容重传不重复占盘。
7. **传文字**：几十字节的验证码 / 命令 / 内网地址，不必包装成文件——页面「传文字」卡片里粘贴、发送，对面设备一键复制。见下方限制。
8. **清理中断**：上传中途关页面/断网会留下未传完的临时数据（可能几 GB）。页面「中断的传输」区块可列出并清理（含子目录里的），已传完的文件不受影响。
9. **对面对着你传（设备发现）**：页面「局域网里的其他 FileDrop」卡片列出同网的其他实例（名字 / IP:端口 / 版本）。点「请求上传」→ **对方屏幕**顶部弹出「某某想给你传文件」横幅，对方点「允许」后本页自动跳到对方地址并开始上传；对方点「拒绝」或 90 秒不理，这里会给出明确失败原因。广播被 AP / 防火墙挡住时改用「手动添加」填 `IP:端口`，界面会说明自动发现为什么不可用。
10. **安卓 App**：打开即当主机（**前台服务保活**，锁屏 / 切后台不掉线，通知栏常驻状态）；在「请求上传」成功连过一台电脑后，之后从相册 / 文件管理器**分享**给 FileDrop 就会直接发到那台设备（通知栏显示进度），一步直达。

> 注意：上传需要带令牌的地址（防同 WiFi 其他人乱传）；下载/列表不需要。**便签读写一律要令牌**——
> 里面常是验证码和密码，不能像照片那样对着局域网敞开读。
>
> 便签的「复制」按钮：网页能往系统剪贴板里写的前提是**安全上下文**。电脑本机用
> `http://localhost:28080` 打开算安全上下文，剪贴板 API 可用；手机扫码进来的是
> `http://192.168.x.x`，浏览器直接禁掉剪贴板 API，此时按钮会明确报「复制失败，请长按正文手动选中」。

## 协议简述
详见 `PROTOCOL.md`（v0.5）。要点：
- **设备发现走 UDP 广播 45581，报文里不带配对令牌**；写权限由对方屏幕上的人一键批准换取：
  临时授权 `?g=` 绑来源 IP、30 分钟过期、最多 8 枚，请求走本机服务端代发再整页跳转，因此不需要开 CORS
- 分块 8MiB，三段式：`status` 查缺块 → `POST /api/upload/chunk` 按偏移 `WriteAt` 落盘 → `complete` 收尾
- `complete` 阶段校验位图、算 SHA-256、重命名落盘；缺块返回 400 + `missing` 触发客户端续传
- **`status` 跳过必须过内容指纹门禁**：客户端带 `&fp=<16hex>`（头/中/尾三个 64KiB 窗口双 lane FNV-1a），
  只有同名 + 同大小 + 指纹一致才判 `complete: true`。v0.3 之前只看同名同大小，会把「改过内容重新导出一份」悄悄丢掉
- `complete` 回 `{ sha256, name, reused }`：`name` 是**真实落盘名**（清洗过非法字符或同名避让改过名），前端以它显示
- 文件名五道关卡：路径穿越 / 结尾点空格 / 超长 / **Windows 非法字符清洗** / 保留设备名。
  不清洗 `<>:"|?*` 轻则 500，重则 `a:b` 被 NTFS 当成交替数据流——接口 200 而目录里只剩一个空文件
- `GET /api/notes` 系列**读写都要令牌**（便签里常是验证码），上限 256KiB/条、200 条/8MiB，存在 exe 同级 `filedrop-notes.json`
- 下载 `GET /api/download?name=` 走 `http.ServeContent`，自动支持 `Range`/206
- **残留文件命名必须带 size**：`<name>.<size>.part[.bits]`
  否则同名不同大小的两次上传会共用位图，导致文件被静默写坏且 SHA 校验发现不了
- 有 `.part` 残留时拒绝切换接收目录，否则旧目录里的几 GB 会变成看不见也清不掉的孤儿
- 下载响应头按 RFC 6266 双写 `filename` + `filename*=UTF-8''...`，中文文件名不乱码
- `GET /api/events` 是 SSE 流，文件与便签变动都会推送，所有页面实时同步列表

## 已知限制（1.0 已大幅缓解）
- **iOS Safari** 已适配：单并发上传、blob+share 下载兜底、安全区与触控卡片视图，但超大文件仍受 Safari 内存限制。
- 配对令牌是**弱防护**（同网设备拿到页面即可读取），仅防误传，非安全边界。
  唯一例外是便签：读写一律要令牌。
- 暂不支持设备间直接 P2P（手机↔平板需经电脑中转）；跨网需另加中继/穿透。
- 单文件受接收目录所在文件系统限制（NTFS/exFAT 均可 >4GB）。
- **自动发现依赖 UDP 广播**：45581 这个端口一台机器只能有一个实例占到，同机跑第二个实例时
  它拿不到广播（界面会写明原因），但「手动添加」照常用。跨网段、AP 屏蔽广播、防火墙拦 UDP
  这几种情况下同样只能手动添加；手机热点/隔离模式之间可能根本听不到。
- 临时写授权存在内存里，**服务重启即失效**：对面得重新点一次「请求上传」。
- 便签容量有限（单条 256 KiB / 总计 200 条或 8 MiB，超出从最旧丢弃），存的是文本不是文件。
- 明文 http 源上浏览器禁写系统剪贴板（见上），手机端只能长按手动选中。

## 自测覆盖（v0.5.0 已跑通）
`testclient` 回环（上传 → 下载 → SHA 比对）之外，还验证了：
- 同名不同 size 隔离：先中断 24MB 的 `dup.bin`，再传同名 40MB 版本 → 报告「缺 5 块」（未被旧位图污染），SHA 与回环均一致
- 中文文件名：`Content-Disposition` 正确输出 `filename*=UTF-8''...`
- 乱序断点续传：只传中间块后，`status` 精确返回 `missing:[0,2]`，续传只补 2 块
- 残留清理：列出 → 按名清理 → 清空，已接收文件不受影响
- **浏览器真实链路上传**：不注入任何 DOM、不改 `input[type=file]`（`hidden` 全程保持），
  用 `DataTransfer` 填 `input.files` 后 dispatch `change`，走用户点选那条路
- **400MB 取消 → 点「续传」收尾**：服务端 SHA-256、浏览器 `crypto.subtle`、Python 独立重算三方一致
  （`a035b7e5…c88c8b94`）；下载 `Range` 返回 206 `bytes 100-199/419430400`；结束后无 `.part` / `.bits` 残留
- **非法文件名**：`colon:test.txt` 清洗为 `colon_test.txt` 真实落盘且内容完整；`NUL:` 被设备名关卡拒掉；
  修复前实测会在目录里留下一个 0 字节的 `colon`（NTFS 交替数据流）
- **指纹门禁**：同名同大小但内容不同的文件不再被判完成，正常全量重传；
  内容一致时秒跳过并回 `reused: true`，界面显示「未重复保存」+ 清洗后的真实文件名
  （这一条同时证明了前端 JS 与 Go 的 FNV 实现逐字节一致）
- **便签令牌门禁**：局域网 IP 不带令牌时 GET/POST/DELETE 全部 403、错令牌 403、对令牌 200，
  而 `/api/files` 仍对局域网开放读（对比确认门禁没写错地方）
- **便签 XSS**：正文里的 `<img onerror=…>` 与 `<a href=javascript:…>` 均未生成元素（`imgCount`/`anchorCount` 为 0）
- 便签多行输入、`Ctrl+Enter` 发送、删除、坏 JSON 自愈、原子写（`.tmp` + rename）

### 设备发现与临时授权（v0.5.0）
单测 11 个（`core/peer_test.go`，含真实 UDP socket 收发一轮信标）覆盖：批准前 403 / 批准后分块 200、
换来源 IP 立刻 403、伪造授权 403、授权过期、授权数封顶 8、同 IP 免二次弹窗、拒绝→403、无人确认→408、
四个控制接口缺令牌全 403、`/api/peers` 不泄漏令牌、`to` 只收 IP 字面量、同 IP 并发不擦掉待批准。

双实例实测（同一台 Windows，两个进程都走局域网地址 `192.168.227.110`，来源 IP 非回环）：
- A 手动添加 B → 列表出现 `v0.5.0 · 手动添加`，`打开` / `请求上传` 渲染正常
- A 点「请求上传」→ 按钮变「等待对方确认…」并禁用，状态行提示去对方屏幕；B 页面顶部弹出
  「一枝轻鸿（192.168.227.110）想给你传文件」+ 允许 / 拒绝（SSE 推的，没等轮询）
- B 点「允许」→ 横幅消失、待批准清空，A 拿到 `{grant,url,expires_ms}` 并**自动跳转**到
  `http://192.168.227.110:28093/?g=…`（URL 里没有令牌）
- 在这个只有授权的页面上走用户选文件那条路（`DataTransfer` 填 `input.files` → dispatch `change`）
  → 300000 字节真实落盘，界面「完成 ✓」，服务端 SHA 与磁盘 `sha256sum` 一致
- 同 IP 再请求一次 → 直接复用授权，不重复弹窗；假授权传分块 → 403；无凭证页面 →
  上传被拦并给出明确文案、便签显示需要写权限、批准横幅位置显示「本页没有写权限」说明

### 未验证（诚实记录，勿当成已通过）
- **安卓真机**：所有链路都在 Windows 上的真实浏览器里跑通，但没有真机在手，
  手机浏览器的分块吞吐、内存表现、iOS 限制均未实测（P2 仍待做）。
- **便签「复制」成功路径**：自动化环境里页面板被隐藏，浏览器直接拒绝写剪贴板，
  只验证到失败降级文案；成功分支需要你在本机点一次确认。
- **两台真实设备之间的自动发现**：信标是真实 UDP socket 收发验证的，但两个实例在同一台 Windows 上
  只能有一个抢到 45581，所以「两台机器互相自动出现在列表里」这条路径（含真机首次弹出的
  Windows 防火墙允许提示、AP 是否转发广播）还没实测，上面的实测走的是「手动添加」。
- **界面上的点击**：自动化环境的浏览器面板处于隐藏状态（`visibilityState=hidden`），
  截图与真实指针事件都被浏览器拒绝。因此「添加 / 请求上传 / 允许」是向页面里那个真按钮
  dispatch 原生 `click` 事件触发的（跑的是用户点同一个按钮走的同一个监听器与同一批请求），
  但没有指针坐标、也没有截图。你本机点开一次即可补齐视觉确认。

### 关于开机自启
本项目**不做**开机自启 / 常驻后台。需要传文件时手动双击 `filedrop-tray.exe`，
用完从托盘菜单「退出」即可。这样服务不会长期挂在局域网上，干净也更省心。
